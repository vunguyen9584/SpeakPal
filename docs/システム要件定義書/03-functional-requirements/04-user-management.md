# ユーザー管理 (User Management)

> このファイルはユーザー管理に関する機能要件を定義します: FR-011, FR-012, FR-013

---

## FR-011: ユーザー登録

### 説明

新規ユーザーがアカウントを作成できる機能。メールアドレスまたはソーシャルログイン（Google/Apple）で登録可能。

### アクター

- ゲストユーザー（未登録ユーザー）

### 事前条件

- ユーザーがアプリをインストール済みである
- インターネット接続が有効である

### メインフロー

1. ユーザーが「新規登録」ボタンをタップする
2. システムが登録画面を表示する
3. ユーザーがメールアドレスを入力する
4. ユーザーがパスワードを入力する（2 回確認）
5. ユーザーがユーザー名を入力する
6. ユーザーが利用規約に同意する
7. システムが入力内容をバリデーションする
8. システムが確認メールを送信する
9. ユーザーがメール内のリンクをクリックして確認する
10. システムがアカウントを有効化する
11. システムがレベル選択画面に遷移する

### 代替フロー

**AF-011-1:** ソーシャルログインで登録

1. ユーザーが「Google で登録」または「Apple で登録」をタップする
2. システムが OAuth 認証画面にリダイレクトする
3. ユーザーがソーシャルアカウントで認証する
4. システムがプロフィール情報を取得する
5. システムがアカウントを作成する
6. システムがレベル選択画面に遷移する

### 例外フロー

**EF-011-1:** メールアドレスが既に登録済みの場合

1. システムがエラーメッセージを表示する
2. ログイン画面へのリンクを表示する

**EF-011-2:** パスワードが要件を満たさない場合

1. システムがバリデーションエラーを表示する
2. パスワード要件を説明する

**EF-011-3:** 確認メールの有効期限切れ

1. システムがエラーメッセージを表示する
2. 再送信オプションを提供する

### 事後条件

- ユーザーアカウントが作成される
- ユーザーがログイン状態になる
- レベル選択が完了していない状態でマークされる

### ビジネスルール

| ルール ID | ルール                                  |
| --------- | --------------------------------------- |
| BR-022    | メールアドレスは一意である必要がある    |
| BR-023    | パスワードは 8 文字以上、英数字混合必須 |
| BR-024    | 確認メールの有効期限は 24 時間          |
| BR-025    | ソーシャルログイン時はメール確認不要    |

### バリデーションルール

| フィールド         | タイプ  | 必須 | バリデーション                        |
| ------------------ | ------- | ---- | ------------------------------------- |
| メールアドレス     | String  | Yes  | 有効なメール形式、最大 255 文字       |
| パスワード         | String  | Yes  | 8-128 文字、英字と数字を 1 つ以上含む |
| パスワード（確認） | String  | Yes  | パスワードフィールドと一致            |
| ユーザー名         | String  | Yes  | 3-30 文字、英数字とアンダースコアのみ |
| 利用規約同意       | Boolean | Yes  | true である必要がある                 |

## FR-012: ログイン/認証

### 説明

登録済みユーザーがシステムにログインして認証される機能。メール/パスワードまたはソーシャルログインに対応。

### アクター

- 登録済みユーザー

### 事前条件

- ユーザーがアカウントを持っている
- アカウントがアクティブである
- インターネット接続が有効である

### メインフロー

1. ユーザーがログイン画面を開く
2. ユーザーがメールアドレスを入力する
3. ユーザーがパスワードを入力する
4. ユーザーが「ログイン」ボタンをタップする
5. システムが認証情報を検証する
6. システムがセッショントークンを発行する
7. システムがホーム画面に遷移する

### 代替フロー

**AF-012-1:** ソーシャルログイン

1. ユーザーが「Google でログイン」または「Apple でログイン」をタップする
2. システムが OAuth 認証画面にリダイレクトする
3. ユーザーがソーシャルアカウントで認証する
4. システムがトークンを検証する
5. システムがセッションを開始する
6. システムがホーム画面に遷移する

**AF-012-2:** 「ログイン状態を保持」オプション

1. ユーザーが「ログイン状態を保持」にチェックする
2. システムがリフレッシュトークンを発行する（30 日間有効）
3. 次回アプリ起動時に自動ログインする

### 例外フロー

**EF-012-1:** 認証失敗（パスワード不一致）

1. システムがエラーメッセージを表示する
2. 失敗回数をカウントする
3. 5 回連続失敗でアカウントを一時ロックする（15 分間）

**EF-012-2:** アカウントがロックされている場合

1. システムがロック状態を通知する
2. ロック解除までの残り時間を表示する

**EF-012-3:** アカウントが無効化されている場合

1. システムがエラーメッセージを表示する
2. サポートへの連絡方法を案内する

### 事後条件

- ユーザーがログイン状態になる
- セッショントークンが発行される
- 最終ログイン日時が更新される

### ビジネスルール

| ルール ID | ルール                                       |
| --------- | -------------------------------------------- |
| BR-026    | セッショントークンの有効期限は 1 時間        |
| BR-027    | リフレッシュトークンの有効期限は 30 日       |
| BR-028    | 5 回連続認証失敗でアカウントを 15 分間ロック |
| BR-029    | ソーシャルログイン時はパスワード不要         |

### バリデーションルール

| フィールド     | タイプ  | 必須 | バリデーション   |
| -------------- | ------- | ---- | ---------------- |
| メールアドレス | String  | Yes  | 有効なメール形式 |
| パスワード     | String  | Yes  | 空でないこと     |
| ログイン保持   | Boolean | No   | デフォルト false |

## FR-013: パスワード変更

### 説明

ユーザーがパスワードを変更できる機能。ログイン中の変更とパスワードリセット（忘れた場合）の両方に対応。

### アクター

- 登録済みユーザー

### 事前条件

- ユーザーがアカウントを持っている
- （ログイン中の変更の場合）ユーザーがログイン済みである

### メインフロー（ログイン中の変更）

1. ユーザーが設定画面から「パスワード変更」を選択する
2. システムがパスワード変更画面を表示する
3. ユーザーが現在のパスワードを入力する
4. ユーザーが新しいパスワードを入力する（2 回確認）
5. システムが現在のパスワードを検証する
6. システムが新しいパスワードをバリデーションする
7. システムがパスワードを更新する
8. システムが成功メッセージを表示する
9. システムが全てのセッションを無効化する（オプション）

### 代替フロー

**AF-013-1:** パスワードリセット（忘れた場合）

1. ユーザーがログイン画面で「パスワードを忘れた」をタップする
2. システムがメールアドレス入力画面を表示する
3. ユーザーが登録メールアドレスを入力する
4. システムがパスワードリセットメールを送信する
5. ユーザーがメール内のリンクをクリックする
6. システムがパスワードリセット画面を表示する
7. ユーザーが新しいパスワードを入力する（2 回確認）
8. システムがパスワードを更新する
9. システムがログイン画面に遷移する

### 例外フロー

**EF-013-1:** 現在のパスワードが不正

1. システムがエラーメッセージを表示する
2. 再入力を促す

**EF-013-2:** 新しいパスワードが要件を満たさない

1. システムがバリデーションエラーを表示する
2. パスワード要件を説明する

**EF-013-3:** リセットリンクの有効期限切れ

1. システムがエラーメッセージを表示する
2. 再送信オプションを提供する

**EF-013-4:** 新旧パスワードが同じ

1. システムがエラーメッセージを表示する
2. 異なるパスワードの入力を促す

### 事後条件

- パスワードが更新される
- パスワード変更通知メールが送信される
- （オプション）他のセッションが無効化される

### ビジネスルール

| ルール ID | ルール                                                 |
| --------- | ------------------------------------------------------ |
| BR-030    | パスワードリセットリンクの有効期限は 1 時間            |
| BR-031    | 新しいパスワードは過去 3 回と異なる必要がある          |
| BR-032    | パスワード変更後に通知メールを送信する                 |
| BR-033    | ソーシャルログインのみのユーザーはパスワード設定が必要 |

### バリデーションルール

| フィールド               | タイプ | 必須  | バリデーション                        |
| ------------------------ | ------ | ----- | ------------------------------------- |
| 現在のパスワード         | String | Yes\* | ログイン中の変更時のみ必須            |
| 新しいパスワード         | String | Yes   | 8-128 文字、英字と数字を 1 つ以上含む |
| 新しいパスワード（確認） | String | Yes   | 新しいパスワードフィールドと一致      |
